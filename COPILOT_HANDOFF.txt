WhatFraud — GitHub Copilot 인수인계 문서

이 파일은 현재 WhatFraud 프로젝트의 목표와 구현 상태를 GitHub Copilot에 전달하기 위한 작업 지시서입니다. Copilot은 먼저 이 문서와 아래에 지정된 파일을 읽은 뒤, 기존 동작을 보존하면서 필요한 변경만 이어서 구현합니다.

## 1. 프로젝트 목표

`WhatFraud`는 청년 이용자가 휴대폰으로 받는 연락을 직접 확인하고 `정상 / 주의 / 사기`로 판별하는 교육용 시뮬레이션 게임입니다.

- 실제 금융·도박 사기에서 반복되는 심리 조종 구조를 체험하게 한다.
- 처음에는 투자사기와 도박사기에 집중한다. 아르바이트 사기 콘텐츠는 현재 범위에서 제외한다.
- 2D 도트풍 마을과 휴대폰 화면을 사용자가 자유롭게 전환한다.
- 마을에서는 집·은행·카페·경찰서·도서관 등을 조사하고, 핵심 플레이는 휴대폰 앱에서 진행한다.
- 연락을 많이 맞힐수록 점수를 얻고, 판정 후 위험 신호와 안전한 확인 행동을 복기한다.
- 사기 연락만 보여 주지 말고 정상 금융 알림과 위험하지만 사기는 아닌 권유도 섞어 플레이어가 실제처럼 판단하게 한다.

## 2. 현재 구현된 UX

### 시작 화면

- 전용 픽셀 배경, 게임 제목, 짧은 안내 문구, `시뮬레이션 시작` 버튼이 있다.
- 제목과 한국어 UI는 읽기 쉬운 글꼴과 정렬을 우선한다.
- 불필요한 두꺼운 테두리와 장식은 줄이고 배경과 버튼 대비를 활용한다.

### 마을 / 휴대폰 전환

- 마을과 휴대폰은 동시에 보이지 않는다.
- 하단 전환 버튼으로 `마을`과 `휴대폰`을 자유롭게 오간다.
- 마을은 클래식 휴대용 게임기풍 2D 도트 자산을 사용한다.

### 휴대폰 OS 화면

- 잠금 화면: 시간·날짜·알림 카드·잠금 해제 버튼
- 홈 화면: 배경화면, 위젯, 앱 그리드, 하단 독
- 앱: 메시지, 전화, 가상 은행, 가상 증권, 브라우저, SNS, 달력, 메모, 연락처, 안전센터, 설정, 사진
- 작은 화면과 긴 한국어 문장이 깨지지 않도록 `min-height: 0`, 오버플로, 줄바꿈을 유지한다.

### 연락 유형

`app/game-data.ts`의 `ContactMode`는 다음 세 가지다.

- `chat`: 실제 대화처럼 답장할 수 있는 DM. 브라우저 Qwen을 우선 사용한다.
- `notice`: 공식 은행·증권 앱의 웹 발신 또는 앱 안내문. 읽기 전용이다.
- `link`: 일방형 문자·광고 링크. 읽기 전용이며 링크를 눌러 교육용 가상 페이지를 확인한다.

`notice`와 `link`에는 답장 입력창을 표시하지 않는다. “답장할 수 없습니다”와 같은 별도 설명 문구도 넣지 말고, 진짜 휴대폰처럼 자연스럽게 확인만 가능하게 한다.

## 3. 현재 LLM 구조

유료 API를 사용하지 않는 것이 기본이다.

### 브라우저 Qwen 기본값

`app/browser-qwen.ts`에서 Transformers.js를 CDN 동적 import하고, 방문자 브라우저의 WebGPU에서 양자화 ONNX 모델을 실행한다.

```text
모델: onnx-community/Qwen2.5-0.5B-Instruct
Transformers.js: https://cdn.jsdelivr.net/npm/@huggingface/transformers@3.8.1/+esm
실행 장치: WebGPU
dtype: q4f16
```

- 모델은 첫 대화 시 내려받고 브라우저 캐시를 재사용한다.
- WebGPU가 없거나 모델 준비·생성이 실패하면 내장 후보 대사로 자동 전환한다.
- `app/game-client.tsx`의 `llmMode` 기본값은 `browser`다.
- 설정 화면에서 선택적으로 `내 로컬 서버`를 사용할 수 있다. 로컬 서버는 llama.cpp의 OpenAI 호환 `/v1/chat/completions` 엔드포인트를 사용한다.
- 브라우저 Qwen의 대화가 서버로 전송되지 않는다는 안내를 설정 화면에 표시한다.

### LLM 안전 경계

- LLM은 상대방의 대사만 생성한다.
- 정답, 점수, 위험 신호, 판정 결과는 코드가 결정한다.
- 모델 출력에 URL, 실제 계좌번호, 전화번호 패턴, 시스템 프롬프트 노출, 범죄 실행·수사 회피 지시가 들어가면 거부하고 후보 대사로 전환한다.
- 실제 작동하는 사기 링크·계좌번호·개인정보·악성 앱은 콘텐츠에 넣지 않는다.
- 사기범 대사를 만들더라도 게임 밖에서 재사용할 수 있는 구체적인 범죄 실행 절차는 생성하지 않는다.

## 5. 현재 시나리오 방향

사례는 다음을 혼합한다.

- 정상: 실제 은행 또는 증권 앱의 거래·보안 안내
- 주의: 과장된 투자 권유지만 즉시 송금·개인정보 요구가 없는 경우
- 사기: 투자리딩방, VIP 종목방, 도박 예측방, 손실 보상·피해금 회수 사기

친구가 소개하는 VIP 종목방처럼 청년이 실제로 겪을 수 있는 관계 압박을 사용하되, 특정 실존 업체·인물·서비스를 지목하지 않는다. 대화는 설교식으로 만들지 말고, 친근함·조급함·소속감·손실 만회 심리를 섞어 플레이어가 질문을 통해 단서를 찾게 한다. 정상 사례도 섞어야 한다.

## 6. Copilot에게 요청할 작업 순서

1. `app/game-client.tsx`, `app/game-data.ts`, `app/browser-qwen.ts`, `app/globals.css`를 먼저 읽는다.
2. 기존 `chat / notice / link` 동작을 깨뜨리지 않는다. 특히 `notice`와 `link`의 답장 UI를 다시 추가하지 않는다.
3. 브라우저 Qwen을 유료 API나 서버 필수 구조로 바꾸지 않는다. WebGPU 실패 시 후보 대사 전환을 유지한다.
4. 새 사례를 추가할 때는 다음을 모두 작성한다.
   - 사례 ID와 연락 유형
   - 초기 메시지 또는 안내문
   - 정상/주의/사기 정답과 위험 신호
   - 플레이어가 확인할 공식 경로와 권장 행동
   - `chat` 사례인 경우 대화 프로필·추천 질문·주제별 후보 대사
5. 모든 사용자 입력은 화면에 안전하게 표시하고, 실제 개인정보 입력을 유도하지 않는다.
6. 한국어 글꼴, 줄바꿈, 모바일 폭에서 긴 문장·URL이 깨지지 않는지 확인한다.
7. 변경 후 아래 검증 명령을 실행한다.

```bash
pnpm install
pnpm lint
pnpm build
```

TypeScript 오류, ESLint 오류, `notice/link` 입력창 노출, 브라우저 Qwen 실패 시 무한 로딩이 있으면 수정한다.

## 7. 배포 목표

정적 호스팅에서 방문자 브라우저가 직접 Qwen을 실행하는 것이 목표다. 별도 유료 API 키나 상시 서버를 요구하지 않는다.

- GitHub 저장소: `https://github.com/hoyhoy1227/whatfraud`
- 예정 테스트 주소: `https://hoyhoy1227.github.io/whatfraud/`
- GitHub Pages가 실제로 동작하려면 저장소의 Pages/Actions 배포 설정을 별도로 확인해야 한다.
- 모델 가중치와 튜닝 결과는 용량 때문에 저장소에 포함하지 않는다.

## 8. 인수인계 시 주의사항

- 이 문서는 기존 구현을 대체하는 설계서가 아니라, 현재 코드의 의도와 안전 경계를 설명하는 인수인계 문서다.
- 기존 자산과 변경사항을 삭제하거나 초기화하지 않는다.
- 사기 예방 교육 목적을 벗어나 실제 사기를 실행하는 데 사용할 수 있는 대사·링크·계좌·스크립트를 추가하지 않는다.
- 모델이 생성한 문장을 판정 로직으로 사용하지 않는다. 판정은 반드시 구조화된 사례 데이터와 코드가 담당한다.
- 새 기능을 추가할 때는 브라우저에서 모델을 실행할 수 없는 이용자도 후보 대사로 전체 게임을 끝까지 플레이할 수 있어야 한다.
