# 사기방지위원회 — 개발 시행착오

목적: AI를 통해 단순 사기 사례 재현보다 고정적이고 반복적인 대화를 줄이고 실제 사기 상황에 처한 것과 같은 체험을 하는 것이 목적이다.

## 문제와 목표
- 전체 흐름에 어긋나거나 인물 설정에서 벗어나지 않는 대화 생성
- 낯선 연락을 정답으로 분류하는 데서 그치지 않고, 친숙함·화면 속 수치·손실 회복 기대에 따라 달라지는 선택을 체험하게 만들기.
- 같은 하루의 인물·거래·기록을 이어 주면서, 안전한 선택을 한 플레이어에게도 다음 상황이 자연스럽게 연결되게 만들기.
- AI가 없어도 진행되며, 생성된 답장이 사건 사실·잔액·결말을 임의로 바꾸지 않게 하기.

## AI를 진행 엔진에서 분리한 이유

- 생성 응답은 표현과 제한된 반응 범주를 담당하고, 거래·단서·진행은 작성 데이터와 이벤트 엔진이 결정합니다.
- 초기에는 자유 질문을 보조했지만 일회성 인물 메시지와 지정된 결정 메시지로 범위를 좁혔습니다. 현재 공개 기준은 사건별 2/2/1·전체 최대 5회입니다.
- 실응답 오류·지연·예산 소진 때 준비된 메시지와 건너뛰기로 계속 진행할 수 있습니다.
- 원문은 진행 저장에 넣지 않고 시도·반응·후속 행동만 저장합니다.
- 공개 v76의 결정 메시지·첨부 반응·품질 보완·행동 근거 보고서를 실행 코드 및 검사와 함께 저장소 기준으로 반영했습니다.

## 현재 남은 과제

- 이후 변경에서도 공개 소스·저장 호환·검증·배포 기록을 함께 갱신하기.
- 실제 모바일 키보드·주소창·뒤로가기·긴 대화와 글자 확대 검수.
- 관찰을 통한 플레이 시간·설명 이해도 확인. 사용자 반응과 개선 성과는 확인 필요.
- 실제 시연 빌드의 자산·서비스 이용 조건과 특정 출품 요건 확인.
- 실응답 품질 평가는 기본 자동 검사와 분리해 필요한 범위만 실행.

우선순위와 완료 조건은 [ROADMAP](ROADMAP.md)에서 관리합니다. 이력의 상세 날짜·원문 변경은 Git 커밋을 기준으로 확인합니다.
