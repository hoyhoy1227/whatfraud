# WhatFraud — 수익률 24시

> **한 줄 소개**: 스마트폰 안에서 하루 동안 벌어지는 금융 사기 상황을 체험하고, 선택의 결과를 되짚는 3막 인터랙티브 게임입니다.
>
> **핵심 가치**: 정답 맞히기보다 **확인 행동(검증·보류·차단·기록 보관)**의 중요성을 플레이 경험으로 전달합니다.

[공개 데모](https://whatfraud-demo.hoyhoy1227.chatgpt.site)

## 게임 개요

| 항목 | 내용 |
| --- | --- |
| 장르 | 내러티브 기반 인터랙티브 체험 게임 (사기 대응 학습형) |
| 플랫폼 | 웹(모바일 우선 UI, 데스크톱은 단일 휴대폰 프레임 집중형) |
| 플레이 방식 | 메시지/연락처/은행/브라우저/메모 앱을 오가며 행동 선택 |
| 플레이어 목표 | 각 연락의 주장과 기록을 대조해 피해를 줄이고 하루를 마무리 |
| 예상 플레이 흐름 | 도입(일상) → 1막 지인 사칭 → 2막 가짜 투자 리딩방 → 3막 피해 회수 사칭 → 결말/되감기 |

## 플레이 루프 (핵심 진행 구조)

1. **연락 수신**: 메시지/알림으로 새로운 사건이 시작됩니다.
2. **기록 확인**: 앱별 증거(대화·거래·공식 안내·메모)를 확인합니다.
3. **행동 선택**: 보류, 차단, 독립 확인, 가상 송금, 기록 보관/접수 등을 고릅니다.
4. **상태 전이**: 엔진이 이벤트를 재생해 잔액·연락 상태·결과를 계산합니다.
5. **회고/재도전**: 결말과 되감기에서 선택 전후 인과를 확인합니다.

## 3막 사건 구조와 엔딩

| 막 | 주요 사건 | 플레이 핵심 |
| --- | --- | --- |
| 1막 | 준호 지인 사칭 | 저장된 연락처와 현재 대화의 신원 분리 확인 |
| 2막 | 가짜 투자 리딩방 | 수익 화면 vs 은행 원장 불일치 대조 |
| 3막 | 피해 회수 사칭 | 손실 회복 심리를 노리는 추가 요구 판별 |

### 엔딩 구조

- 기본 결말 3종: **지켜낸 하루 / 멈춰 세운 하루 / 아직 끝나지 않은 하루**
- 결말은 점수 대신 실제 행동 로그(확인·중단·차단·거래 이력)에 따라 계산됩니다.

> ⚠️ 스포일러 주의: 상세 분기와 대사 맥락은 [ROADMAP.md](./ROADMAP.md)와 게임 본편에서 확인하세요.

## 핵심 기능 및 구현 포인트

- **행동 중심 진행**: `판정 제출`보다 앱 탐색·기록 확인·결정의 연쇄를 중심으로 설계
- **이벤트 재생 기반 저장 복원**: 저장값을 신뢰하지 않고 이벤트를 재생해 상태 복원
- **가상 거래 안전장치**: 동일 거래 ID 중복 실행 방지, 실제 송금/외부 통화 없음
- **제한적 AI 사용**: 선택적 NPC 메시지 보조(지수/준호), 사건 사실·거래 결과는 코드가 결정
- **콘텐츠 검증 파이프라인**: 스키마/정적 규칙/출시 검사를 스크립트로 자동화

## 게임 프로젝트 구조

아래는 **실제 디렉터리 기준 구조**입니다.

```text
whatfraud/
├─ app/                # 게임 런타임(Next.js App Router), UI, 상태 전이, API
│  ├─ story/           # 스토리 엔진/프레젠테이션/메시지 흐름
│  └─ api/ai-chat/     # 선택적 AI 대화 API
├─ content/            # 시나리오 원본·스키마·생성물·보관 아카이브
│  ├─ cases/           # 3막 사건 JSON 원본
│  ├─ schema/          # 콘텐츠 스키마
│  ├─ generated/       # 빌드 산출(cases.json)
│  └─ archive/         # 비활성/이전 버전 사건 보관
├─ db/                 # 저장 데이터 계층(Drizzle 스키마)
├─ public/             # 정적 리소스(픽셀 아트, OG 이미지, 파비콘)
├─ scripts/            # 콘텐츠 빌드/검증/출시 점검/스토리 테스트 스크립트
├─ drizzle/            # DB 마이그레이션 메타데이터
└─ *.md                # 운영/로드맵/보안/권리/출품 문서
```

- 구조 정리 원칙과 “왜 현재는 물리적 파일 이동보다 논리적 분리 설명을 우선했는지”는 [docs/PROJECT_STRUCTURE.md](./docs/PROJECT_STRUCTURE.md)에 정리했습니다.

## 기술 스택 및 아키텍처 개요

| 영역 | 사용 기술 |
| --- | --- |
| 프론트엔드 | Next.js 16, React 19, TypeScript |
| 런타임/빌드 | vinext, Vite, ESLint |
| 데이터 | JSON 기반 콘텐츠 + Drizzle ORM 스키마 |
| 운영 연동 | Cloudflare Workers/D1(운영 문서 기준) |
| AI(선택) | Gemini 3.5 Flash-Lite (서버 측 보호 로직 하 제한 사용) |

아키텍처 요약:

1. `content/cases/*.json` 원본을 `scripts/build-content.mjs`로 검증·통합
2. `content/generated/cases.json`을 `app/game-data.ts`, `app/story/engine.js`에서 로드
3. `app/story/*`가 상태 전이/표시/상호작용을 분리해 플레이 흐름 구성
4. 선택적 AI는 `app/api/ai-chat/route.ts`에서 예산/입력/출력 가드 후 응답

## 콘텐츠 제작 · 빌드 · 검증 흐름

1. 사건 원본 작성: `content/cases/*.json`
2. 스키마/규칙 검증 + 생성물 갱신: `pnpm content:build`
3. 대화 안전/품질 정적 검사: `pnpm dialogue:check`
4. 출시 전 일관성 검사: `pnpm release:check`
5. 코드 스타일 검사: `pnpm lint`

상세 운영 절차(배포/키 관리/장애 대응)는 [OPERATIONS.md](./OPERATIONS.md)에서 관리합니다.

## 실행 방법

### 요구 사항

- Node.js `>= 22.13.0`
- pnpm

### 로컬 실행

```bash
pnpm install --frozen-lockfile
pnpm dev
```

### 주요 npm scripts

| 명령 | 설명 |
| --- | --- |
| `pnpm dev` | 로컬 개발 서버 실행 |
| `pnpm content:build` | 콘텐츠 통합 생성 |
| `pnpm content:check` | 생성물 최신 여부 확인 |
| `pnpm dialogue:check` | 대화 검증 |
| `pnpm release:check` | 릴리스 일관성 검사 |
| `pnpm lint` | ESLint 검사 |
| `pnpm build` | 프로덕션 빌드 |
